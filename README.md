## 扩展约定

**导航固定为四页，不随资料增长。** 外部视频按「一页一条」挂在内容最相关的那一页末尾（`.vcard` 组件），挂进来的同时写清「为什么挂这条」。

新增一份**成篇文字**资料：才单独开一页，并把四页导航、页脚、跳转卡、`404.html` 与本文一并同步。

外链一律 `target="_blank"`，商业与未核实来源额外带 `nofollow`；站内不加载任何外部资源，链接失效不影响阅读。

**所有对外推荐集中在 `picks.html`「站长推荐」，首页不堆链接。** 该页分三节：01 相关视频、02 付费推荐、03 抖音推荐。以后新增视频、商品、短视频链接一律往这一页加条目，**不再新增页面、不再新增导航项**——导航固定五项。

首页只保留「同一说法的其他版本」列表（`.variants`），因为它是核查论证的一部分（证明同一框架在多个账号间独立流传），属于证据而非推荐。

**推荐位只挂视频分享链接（`v.douyin.com/…/`），不挂账号主页。** 抖音用户页是纯客户端渲染，服务端不返回昵称与简介（分享页、iteminfo 接口、用户 share 页、网页搜索四条路都试过），程序核实不了就只能写成「在抖音关注这位博主」这类没有信息量的空文案，因此本站不再收账号主页。希望被推荐或曝光的，统一走仓库 [Issues](https://github.com/dujeongil-galaxy/dating-data-factcheck/issues)，由站长判断，不保证收录。

**删掉的推荐不留存档。** 页面上不设「已下线推荐」列表，本变更记录里也只剩事件本身，不复述被删条目的昵称、抖音号与联系方式。但须说清边界：仓库是公开 git 历史，删除前的版本仍能从提交记录里翻出，本站无法阻止，也没有能力抹掉——这是「不保留存档备份」这句话能兑现到的限度。

**同题视频进首页的「同一说法的其他版本」列表**（`.variants`），不占用各页的那一条视频位。判断标准：如果一条视频只是把首页已经核查过的同一个说法换个账号再说一遍，它属于「传播样本」，归这个列表；只有带来新角度的内容才配挂到某个页面末尾。

**归属判断优先于「有链接可挂」。** 曾试挂的两条已撤：「73 天闪离分 1500 万房产」讲的是婚后共同财产分割，与本页讲的恋爱期借款/赠与是两套法律规则，并列会误导读者以为恋爱转账也能照样追回（与本页「520、1314 不可追回」直接冲突）；「大龄剩女能有啥筹码」把人按年龄条件折算成筹码，与双向约定一页「两个独立灵魂互相吸引」的主张相反。行动守则页那条「抽象私信」保留，但已注明它是吐槽向娱乐内容、不是论据。

**同一款产品的多平台入口挂在同一张卡里，不另开条目。** 否则「站内唯一一条」这类计数说法会当场失真。平台标价一律不代填数字，只写「以商店页实时显示为准」，并说明页面原文里已经过期的促销话术——抄过来就是假价格。

**来源标注。** 本站正文引用的《瞬间自信》及「觉自心」「小我意识」「心力」等术语出自成真恋爱学（迷上我，mishangwo.com），已在 `anti-scam.html` 就地标注出处，并声明该站为付费教程商业站点、站长为其会员。

## CI 检查失败了怎么修

本仓库有一个自动检查（`.github/workflows/readme-check.yml`，工作流名 **站点检查**），在你改动 README 或任一 HTML 页面后自动运行，分两步：

**第一步 `check_readme.py`** 管 README.md：占位符残留、Markdown 表格列数一致性、外链可达性。

**第二步 `check_site.py`** 管所有 HTML 页面，共 12 项：

- 首行必须是 `<!DOCTYPE html>`（否则进怪异模式）
- `<html lang>`、`<title>`、viewport meta 是否齐备
- 标签是否配对闭合
- 是否有占位符残留
- 是否缺 `<noscript>` 降级、是否缺 CSS 层 `prefers-reduced-motion`
- **零外部依赖**：出现 `script src=http`、`img src=http`、外部 `link stylesheet` 直接判失败
- `target="_blank"` 是否都带 `rel="noopener"`
- 站内链接 `./xxx.html` 指向的文件是否真的存在
- 窄屏溢出风险：按渲染文本算最长不可断词，超过 226px 预算（320px 视口扣除容器内边距与序号区）即告警
- 外链 HTTP 可达性
- **跨页一致性**：各页导航与页脚的链接集合必须完全相同；`.nojekyll` 必须存在

失败时 CI 显示红叉，输出里用 `✗` 标出文件、行号和原因。

### 一、占位符 / 待办标记

输出形如：`✗ README.md:81  命中 'TODO'`

会被判命中的字面量：`<user>`、`<repo>`、`your-username`、`your_repo`、`TODO`、`FIXME`、`XXX`、`example.com`。

两种情况两种修法：

- **真的忘了替换** → 把那处改成真实内容。
- **只是在讨论这个词本身** → 用反引号把它包起来。检查器会跳过反引号内的文本，所以带反引号的 `TODO` 不会报错，裸写就会。

### 二、表格列数不一致

输出形如：`✗ README.md:8  数据行 3 列 != 表头 2 列`

Markdown 表格每一行的竖线数量必须与表头完全相同，分隔行也要一样多。代码块里的竖线不算。

本 README 已不使用宽表格（手机上会挤成一列窄条），新增内容优先照「页面」小节的单列条目写法，不要再引入表格。

### 三、外链不可达

输出形如：`✗ https://…  -> HTTP 404`

按状态码分别处理：

按状态码分别处理（这里刻意不用表格演示，因为表格在手机上会挤，且列数必须严格对齐，容易自己踩坑）：

- **HTTP 404 / 410 / 5xx**：链接确实坏了。换成新地址；如果原视频已下架且没有新地址，就把整条删掉，不要留一个点不开的连接。
- **超时、DNS 失败、连接被重置**：多半是临时网络问题，按下面「重跑」再来一次即可，不必改文件。
- **HTTP 401 / 403 / 429**：**不会让 CI 变红**，只会列进「疑似限流」提示里。GitHub 自己的页面就经常对检查用的请求返回 403，这不代表链接失效。
- **抖音链接（`douyin.com` / `v.douyin.com`）**：**CI 一律不去判断**，会列进「无法自动验证」。因为抖音对任何程序化请求都返回 404（包括故意编造的不存在 ID），拿 404 当死链会让 CI 永久红着、检查器当场作废。这类链接只能你在 App 或浏览器里人工确认，目前站内有 6 条。

### 不用等 CI，本地先跑

在仓库目录下执行：

```bash
python .github/scripts/check_readme.py README.md
python .github/scripts/check_site.py
echo $?
```

第一条查 README，第二条查全部 HTML 页面。最后一行输出 `0` 是通过，`1` 是有问题。**推送之前先跑一遍这两条**，比等 CI 红了再回来修快得多。

### 在 GitHub 上查看失败详情

1. 打开仓库页 <https://github.com/dujeongil-galaxy/dating-data-factcheck>
2. 点顶部标签栏的 **Actions**
3. 左侧列表找到 **README 检查**，点那条带红叉的记录
4. 再点名为 **check** 的任务，展开最后一步「检查占位符、表格列数与外链可达性」，就能看到所有 `✗` 行

### 临时失败可以重跑

在失败页面右上角点 **Re-run jobs** → **Re-run all jobs**。网络抖动、限流造成的失败用这个解决，不需要改任何文件。

### Actions 没触发怎么办

**现象**：推送了改动 `README.md` 的提交，但 Actions 列表里只有 `pages build and deployment`，没有 `README 检查`。本站实测遇到过一次。

**先排除配置问题**（两步）：

1. 打开仓库页 → **Actions** → 左侧 **README 检查** → 右上角 **`⋯`** → **View workflow file**，确认文件里 `on: push: paths:` 下面确实列着 `README.md`。
2. 用 `git show --stat <提交号>` 看那次提交改的文件清单，确认里面包含 `README.md`。

两项都对，就是 GitHub 偶发漏触发，不是你的仓库坏了。按成本从低到高处理：

**① 本地自己跑一遍（最推荐，完全不依赖 GitHub）**

```bash
python .github/scripts/check_readme.py README.md
echo $?
```

退出码 `0` 就说明 README 本身没问题。漏触发的代价只是少了一次自动留痕，不影响正确性。

**② 在网页上手动触发**

Actions → README 检查 → 右侧 **Run workflow** → 分支选 `main` → **Run workflow**。注意这条路只在网页上可用，用 API 触发会返回 404（见下一小节）。

**③ 重新推一次让它触发**

**空提交不会触发**——`paths` 过滤要求这次推送真的改到列表里的文件，而空提交什么文件都没动。所以要么真的动一下 `README.md`（加一个空行再删掉也算改动），要么用上面第 ② 种方式。

**④ 不用管它**

本工作流带每周一 01:00 UTC 的定时复跑，单次漏触发最迟一周后就会被覆盖。只有在你急着要这次检查结果时才需要 ①②③。

### 关于手动触发

本检查工作流可在 Actions 页面点 **Run workflow** 手动跑一次。但**用 API 触发会返回 404**：GitHub 要求令牌具备 `workflow` 权限，而本站推送用的 classic 令牌只勾了 `repo`。要能 API 触发就得重建一个带 `workflow` 勾选的令牌，一般没必要——在网页上点按钮即可。

### 不要绕过检查

不要用 `[skip ci]` 这类提交标记跳过这次运行。检查失败说明 README 确实有问题，跳过只是把它留给下一次的自己。
